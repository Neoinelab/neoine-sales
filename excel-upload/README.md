# 계약 Excel 1회성 가져오기

`excel-upload` 디렉터리에서 실행합니다. `run.sh`는 실행 위치를 이 디렉터리로 고정하고,
`uv --project`로 backend의 기존 환경을 사용합니다. 새 패키지는 필요하지 않습니다.

```bash
cd excel-upload
./run.sh contracts_20261123.xlsx --dry-run
./run.sh contracts_20261123.xlsx
```

다른 디렉터리에서도 `경로/excel-upload/run.sh`로 호출할 수 있습니다.
파일명 대신 절대/상대 경로도 가능합니다. 상대 경로는 `excel-upload/` 기준입니다.
`backend/.env`를 기존 `app.config.get_settings()`로 읽습니다. 기존 설정 규칙대로 `APP_*` 환경변수가
파일 값보다 우선하므로 실행 셸에 다른 DB의 `APP_DATABASE_URL`이 설정되어 있지 않은지 확인하세요.
접속 문자열·비밀번호는 출력하지 않습니다. `uv run import_contracts.py`처럼 독립 환경으로 실행하지 마세요.

먼저 이번 변경의 DB 마이그레이션(NULL users/매출금액, 회사명 공백 허용)을 적용해야 합니다.
`--dry-run`은 DB 트랜잭션을 READ ONLY로 설정하여 사용자 매칭과 기존 계약 충돌만 조회합니다.
실제 반영은 전체 행을 검증한 뒤 한 트랜잭션에 저장하며 실패하면 전체 롤백합니다.
계약별 쓰기 동안 Deal·Contact·Vendor 테이블을 잠그므로 사용량이 적은 시점에 실행하세요.

첫 시트의 헤더는 다음 10개가 이 순서대로 있어야 합니다.

| Excel | 저장 방식 |
| --- | --- |
| 고객사명 | 고객 Contact 회사명, 담당자 `유지보수`; 같은 종류·회사명·담당자 재사용 |
| 제조사 | Vendor 이름; 대소문자 무시로 재사용하거나 신규 생성 |
| 제품명 | Deal Product |
| 파트너사 | 파트너 Contact 회사명, 담당자 빈 문자열; 같은 종류·회사명·빈 담당자 재사용 |
| 시작일 / 종료일 | 라이선스 시작·종료일; Excel 날짜 또는 YYYY-MM-DD |
| 상태 | 계약 Note |
| 영업담당 | 기존 활성 sales/admin 사용자의 로그인 아이디 또는 표시 이름과 매칭 |
| 기술담당 | 계약 기술담당 |
| 점검주기 | 월점검→monthly, 분기점검→quarterly, 반기점검→semiannual, 연/년/연간점검→yearly |

점검주기 빈값·없음·파트너사 수행은 `none`(선택 없음)입니다. 상태가 비면 Note도 비어 있습니다.
영업담당 `한국명(영문명)`은 전체 이름 우선, 없으면 괄호 전 이름이나 괄호 안 값과 정확히 매칭합니다.
일치 사용자가 없거나 여러 명이면 행 번호와 함께 중단하며 사용자를 임의로 생성하지 않습니다.

Deal 이름은 `유지보수-<고객사명>-<제품명>`, Users count와 매출금액은 NULL,
매출일·상태변경일은 시작일, Deal 상태는 계약완료/Won, 계약 상태는 발급(신규)입니다.
등록자·수정자는 해당 영업담당이고, 등록시각은 실행 시각입니다. 등록 이력도 남깁니다.
회사명 내부 공백은 보존하고 셀 앞뒤 공백은 제거합니다. 원본 Excel 파일은 수정하지 않습니다.

동일 Deal명이 있으면 고객/Vendor/제품/파트너/영업담당/기간/Note/점검주기/기술담당 및
NULL Users·금액까지 모두 같은 발급(신규) 계약 한 건만 재실행에서 건너뜁니다.
이름은 같지만 값이 다르거나 계약이 여러 건이면 중단합니다. 기존 데이터를 덮어쓰지 않습니다.
Excel 자체에 같은 Deal명이 반복되어도 중단하므로 중복 행이나 기간별 동일 제품은 사전 정리가 필요합니다.

종료 코드 0은 성공, 1은 입력/DB 검증 실패, 2는 CLI 인자 오류입니다.
실제 반영 전 dry-run을 실행하고 DB 백업을 확보하세요.

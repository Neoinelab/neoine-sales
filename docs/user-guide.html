1. 개요

neoine-sales는 영업 기회(Deal)를 한곳에서 기록하고 추적하는 사내 영업 관리 시스템입니다. 영업 담당자는 Deal을 등록하고, 고객과 만날 때마다 Action을 남기고, 진행 단계(Status)와 수주 가능성(Forecast)을 갱신합니다. 시스템은 이 기록으로 다음 일을 대신합니다.

  • 모든 변경을 History에 자동으로 남깁니다. 누가, 언제, 무엇을 무엇으로 바꿨는지 남습니다.
  • Status와 Forecast가 서로 어긋나지 않게 맞춥니다. 예를 들어 계약완료이면 반드시 Won입니다.
  • 기한이 지났거나 오래 갱신되지 않은 Deal에 경고를 붙입니다.
  • 고객·파트너 연락처를 중복 없이 관리하고, 계약서·제안서 같은 첨부 파일을 Deal별로 보관합니다.

화면의 날짜·시각(오늘, 올해·이번 분기 기본값, 등록·수정·수행 시각)은 모두 서버 시간대 기준(운영 서버는 한국 시간)이며 내 PC의 시계·시간대와 관계없습니다. 로그인 직후 서버 시각을 받아 오는 동안 잠깐 “불러오는 중…”이 보입니다.

상단 메뉴는 Dashboard, Deals, Forecast, Reports 순서이고, admin에게만 맨 끝에 Admin이 더 보입니다.

4. Deal의 일생

등록→Action 기록→Status·Forecast·금액 갱신→경고 확인·후속 조치→종결(Won / Lost)
  1. 등록: Deal Name, Owner, 고객, Status, Forecast, 금액, Expected Close, Users를 입력합니다. 시스템이 Deal code를 발급하고 History에 "Deal 등록"을 남깁니다.
  2. 진행: 고객과 통화하거나 미팅할 때마다 Action을 남깁니다. "이번에 한 일"(진행사항)과 "다음에 무엇을 언제까지 할지"(Next Action, Due Date) 중 하나 이상을 적습니다. 목록에는 Next Action이 있는 가장 최근 Action의 Next Action, Due Date, 상태가 표시됩니다. 계획한 일을 마치면 그 Next Action을 종료(수행 또는 미수행)로 표시합니다(7.4).
  3. 단계 갱신: 상황이 바뀌면 Status, Forecast, 금액, Expected Close를 고칩니다. 목록이나 상세 화면에서 바로 바꿀 수 있습니다. 바꿀 때마다 History가 남습니다.
  4. 경고 관리: Due Date가 지났거나 오래 갱신하지 않으면 경고가 붙습니다. 미업데이트 경고는 Action을 남기면 풀립니다. Deal 자체를 고치는 것으로는 풀리지 않습니다(8장).
  5. 종결:
    • 수주하면 Forecast를 Won으로 바꿉니다(또는 Status를 계약완료로 바꿉니다). 둘은 함께 바뀌며 실제 매출금액과 매출일을 확인해 입력합니다.
    • 실패하면 Forecast를 Lost로 바꿉니다.
    • 종결된 Deal에는 경고가 붙지 않습니다.
  6. 재개 또는 삭제:
    • 종결된 Deal도 다시 열 수 있습니다(6장).
    • 잘못 만든 Deal은 삭제할 수 있지만, 딸린 기록까지 모두 사라집니다(16장).

5.2 화면 배치

등록·수정 화면과 상세 화면은 같은 배치를 씁니다. Deal code와 Owner를 포함한 기본 정보는 Deal 정보 칸에 모여 있고, 항목 이름과 값이 한 줄에 나란히 보입니다. 상세 화면에서 값을 눌러 고칠 때도 글자 위치와 모양이 그대로 유지됩니다. Deal code는 등록할 때 시스템이 발급하므로 등록 화면에는 입력란이 없습니다.

상세 화면(/deals/{code})은 탭 세 개로 나뉩니다. 제목(Deal Name)·"← 목록"·삭제 버튼은 탭 위에 있고 탭은 제목 바로 아래에 있습니다. Deal 정보(Status·Forecast·금액·Next Action 등)는 기본 탭인 Deal 상세 탭 안에 있고, 알림은 탭 내용 맨 위에 나와 어느 탭에서나 보입니다.

5.3 수정 방법 세 가지

  • 수정 폼(/deals/{code}/edit): 여러 항목을 한 번에 저장합니다. 바뀐 항목마다 History가 한 건씩 남고, 아무것도 바뀌지 않았으면 History도 수정 시각도 그대로입니다. 폼 저장에서는 최종 Status와 Forecast가 규칙에 맞아야 하며, 맞지 않으면 아무것도 저장되지 않습니다.
  • 목록에서 바로 고치기: Status, Forecast, 금액, Expected Close 네 칸은 목록 화면에서 바로 바꿀 수 있습니다.
  • 상세 화면에서 바로 고치기: 제목(Deal Name)과 Deal 상세 탭의 Deal 정보·고객·파트너·BANT 칸을 그 자리에서 고칠 수 있습니다. Status나 Forecast를 하나만 바꾸면 시스템이 함께 바꿀 값을 물어봅니다(6장).

5.4 BANT Label·Action 유형 입력 규칙

  • 입력한 이름이 기존 항목과 대소문자만 다르면 같은 항목으로 봅니다. 예를 들어 "poc"를 입력하면 기존 "POC"를 쓰고 새로 만들지 않습니다.
  • 새 항목은 저장이 성공할 때만 만들어집니다. 다른 항목 오류로 저장이 거절되면 새 Label·유형도 생기지 않습니다.
  • 수정 화면을 열어 둔 사이 관리자가 이름을 바꾸면, 내가 손대지 않은 칸은 새 이름으로 바뀌고 원래 항목이 그대로 저장됩니다. 옛 이름으로 새 항목이 생기지 않습니다.
  • Label·유형 목록을 불러오지 못하면 오류 안내가 보입니다. 이때 수정 화면의 BANT 칸은 잠기고, 저장해도 기존 BANT 선택은 바뀌지 않습니다.
  • 조회자(user) 역할은 저장할 수 없으므로 새 항목도 만들 수 없습니다.

Owner가 퇴사한 경우: Deal은 그대로 남고 Owner는 "이름(퇴사)"로 표시됩니다. 퇴사자는 Owner로 새로 지정할 수 없으니, 폼으로 저장할 때 재직 중인 영업 담당자로 Owner를 바꿔야 합니다.

6. Status·Forecast 동기화

규칙은 하나입니다. Status가 계약완료이면 Forecast는 반드시 Won이고, Forecast가 Won이면 Status는 반드시 계약완료입니다. 그 밖의 조합은 자유롭습니다. 예를 들어 Status가 "가격협상"이면서 Forecast가 "Lost"인 상태도 허용됩니다. 실패한 시점의 단계를 남기는 용도입니다.

Status나 Forecast 하나만 바꿀 때 이 규칙이 깨질 상황이면, 시스템이 나머지 값을 자동으로 맞추거나 사용자에게 고르게 합니다.

바꾸려는 값시스템 동작
Status → 계약완료Forecast가 자동으로 Won이 됩니다. 매출금액과 매출일을 입력해야 저장됩니다.
Forecast → WonStatus가 자동으로 계약완료가 됩니다. 마찬가지로 매출금액과 매출일이 필요합니다.
Status: 계약완료 → 다른 단계Deal을 다시 여는 변경입니다. Forecast를 Won이 아닌 값 중에서 골라야 합니다.
Forecast: Won → 다른 값Status를 계약완료가 아닌 단계 중에서 골라야 합니다. 기본으로 선택된 값은 없습니다.
Forecast: Lost → 진행 중 값Status를 다시 고르게 합니다. 기본값은 지금의 Status입니다.
그 밖의 변경바꾼 값 하나만 바뀝니다.

함께 바뀐 값은 저장 후 안내 문구로 알려 줍니다. 예: "Status가 '계약완료'로, Forecast가 'Won'으로 함께 변경되었습니다." History에는 "계약완료 (Forecast Won과 함께 변경)"처럼 남습니다.

규칙은 코드의 내부 key로 판단합니다. 그래서 관리자가 "계약완료"의 이름을 "수주"로 바꿔도 규칙은 그대로 동작합니다. 이런 코드는 삭제할 수 없도록 잠겨 있습니다(17.2).

7. Action(진행 활동)

7.1 구성

Action은 Deal 상세의 Actions 탭에서 다룹니다. 쓰기 권한(sales·admin)이 있으면 "Action 추가" 버튼이 보이고, 누르면 제목이 "Action 추가"인 팝업에 등록 폼이 열립니다. Next Action이 있는 가장 최근 Action이 있으면 폼 위에 이전 Update 카드가 함께 보여 지난 계획을 보면서 입력할 수 있습니다. 카드에는 이전 Action의 진행사항·Next Action·Due가 보이며, "이전 Next Action을 진행사항에 채우기"를 누르면 그 Next Action 내용이 진행사항 칸에 들어가고, "저장 시 이전 Next Action을 종료(수행)로 바꿈" 체크박스가 켜진 채로 나타납니다. 그대로 저장하면 새 Action과 함께 이전 Next Action이 종료(수행)로 바뀝니다(종료 시각은 새 Action의 수행 시각, Memo는 그대로, Deal History에 두 줄). 체크를 끄거나 저장하지 않고 닫으면 상태는 그대로입니다. 이전 Next Action이 이미 종료 상태면 체크박스가 나오지 않고, 다른 담당자의 Next Action이면(admin 제외) "다른 담당자의 Next Action이라 상태는 바꾸지 않습니다."가 보입니다. 폼을 연 뒤 다른 사람이 Action을 추가해 이전 Next Action이 바뀌었다면 "이전 Next Action이 바뀌었습니다. 창을 닫고 다시 열어 주세요."와 함께 저장되지 않습니다. 이때 이전 Update 카드가 새 Action으로 바뀌면 채운 내용과 체크가 풀리고 "이전 Update가 바뀌었습니다. 확인 후 다시 채우세요."가 보입니다(진행사항에 적은 글은 그대로). 채우기를 누른 그 Next Action만 종료되므로, 보지 않은 Next Action이 대신 종료되지는 않습니다. (2026-10-26 추가) 목록 행의 "수정"을 누르면 제목이 "Action 수정"인 팝업이 그 Action의 값이 채워진 채로 열립니다(이전 Update 카드와 Status·Forecast 칸은 없음).

  • 저장에 성공하면 팝업이 닫히고 탭 내용 맨 위 알림에 "Action이 등록되었습니다."(함께 바뀐 Status·Forecast 요약 포함) 또는 "Action이 수정되었습니다."가 보입니다.
  • 입력 오류나 서버 오류가 나면 팝업은 열린 채 입력값이 남고, 오류는 팝업 안에 표시됩니다.
  • "취소" 또는 Esc로 닫습니다. 팝업 바깥(배경)을 눌러도 닫히지 않습니다. 닫으면 저장하지 않은 입력은 사라집니다(다시 열면 등록은 빈 폼, 수정은 원래 값). 저장 중에는 닫을 수 없습니다.
  • 팝업 위에 Status·Forecast 동기화 팝업("함께 바꿀 값 선택", "매출 확정")이 열려 있을 때 Esc를 누르면 그 동기화 팝업만 닫히고 Action 팝업과 입력값은 남습니다. 유형 후보 목록이 열려 있을 때의 Esc도 후보 목록만 닫습니다.
  • 영업(sales) 사용자에게는 다른 사람이 기록한 Action의 "수정"·"삭제" 버튼이 숨지 않고 회색(누를 수 없음)으로 보이며, 마우스를 올리면 "본인 Action 또는 admin만 수정할 수 있습니다."(삭제는 "…삭제할 수 있습니다.")가 나옵니다. 조회자(user)에게는 이 버튼이 보이지 않습니다.

7.2 시스템이 정하는 값

  • 수행 일시는 저장한 시각, 담당자는 저장한 사람으로 서버가 채웁니다. 다른 사람 이름으로 기록하거나 날짜를 과거로 돌릴 수 없습니다.
  • 기록할 때의 Status와 Forecast(등록 폼에서 바꿨다면 바꾼 뒤의 값)를 Action에 스냅숏으로 함께 저장합니다. 나중에 Deal이 바뀌어도 "그때 어떤 단계였는지"가 남습니다.
  • 수정할 수 있는 것은 내용(유형·진행사항·Next Action·Due Date·Memo)뿐입니다. 수정 폼에는 Status·Forecast가 없습니다. 수행 일시, 담당자, 스냅숏은 바뀌지 않습니다.
  • 수정할 때 Next Action 상태는 이렇게 됩니다: 종료된 Next Action의 내용이나 Due Date를 고쳐도 상태는 그대로입니다. Next Action을 비우면 상태도 없어지고, 없던 Next Action을 새로 채우면 Open으로 시작합니다.

7.3 Action이 Deal에 주는 영향

  • Next Action이 있는 가장 최근 Action(기준 행)의 Next Action, Due Date, 상태가 Deal의 "다음 진행 계획"으로 목록과 상세 화면 Deal 정보 칸의 Next Action 행에 표시됩니다. 진행사항만 있는 Action은 건너뜁니다. 목록의 Next Action 상태 필터, 기한초과 경고와 기한초과 검색 조건도 이 기준 행으로 판단합니다.
  • Deal의 마지막 업데이트는 진행사항만 있는 것을 포함한 모든 Action 중 가장 최근 수행 시각입니다. Action이 하나도 없으면 Deal 등록 시각입니다. Deal 자체의 수정(목록·상세의 바로 고치기 포함)은 마지막 업데이트를 바꾸지 않습니다. Action을 남기면 미업데이트 경고가 풀립니다.
  • Action의 등록·수정·삭제도 모두 History에 남습니다.

7.5 Action 검색

Deal 상세의 Actions 탭에서 유형(등록된 유형 목록에서 선택), 담당자(퇴사자 포함), 키워드(진행사항·Next Action·Memo에서 찾음, 100자 이내), 수행일, 기한(Due Date), Next Action 상태(전체 / Open / 종료(수행) / 종료(미수행) / 종료(전체))로 걸러 볼 수 있습니다. 정렬은 검색 조건이 아니라 목록 헤더로 합니다(아래 "목록 정렬"). 종료(전체)는 종료(수행)과 종료(미수행)을 함께 고릅니다. 상태를 고르면 Next Action이 없는 Action은 결과에서 빠집니다.

  • 기간 목록을 서버에서 받지 못하면 프리셋 선택지는 고를 수 없고(전체·직접 지정은 가능) 오류 안내가 보입니다. 검색할 때 기간을 받지 못하면 오류를 보이고 결과는 그대로 둡니다.
  • "초기화"를 누르면 모든 검색 조건(유형·담당자·키워드·수행일·기한·Next Action 상태)이 비워지고 직접 지정 날짜도 지워진 뒤 바로 다시 조회합니다.
  • 검색 조건은 주소에 저장되지 않습니다. 다른 탭에 갔다가 돌아오면 조건이 초기화됩니다.

목록 정렬: Actions 목록에서 수행일시 / 담당자 / 유형 / Due Date / 상태 헤더를 누르면 그 열 기준으로 정렬합니다. 같은 헤더를 다시 누르면 오름차순과 내림차순이 바뀝니다. 지금 정렬 중인 열의 헤더에는 ▲(오름차순) 또는 ▼(내림차순)가 보입니다. 다른 열(등록 시점 Status·Forecast, 진행사항, Next Action, Memo)은 정렬할 수 없습니다.

8. 경고와 체류 일수

종결되지 않은(Won·Lost가 아닌) Deal에는 두 가지 경고가 붙을 수 있습니다. 두 경고가 동시에 붙기도 합니다.

경고조건푸는 방법
기한초과(빨강)Next Action이 있는 가장 최근 Action(기준 행)의 Due Date가 오늘보다 앞섬. Next Action 상태와 무관해서 종료한 Next Action도 해당됩니다.새 Next Action과 다음 기한을 담은 Action을 남김(또는 기준 행의 Due Date를 고침)
미업데이트(노랑)마지막 업데이트(모든 Action 중 가장 최근 수행 시각, Action이 없으면 Deal 등록 시각) 후 기준 일수 이상 지남(기본 14일)Action을 남김(진행사항만 있어도 됨). Deal 수정으로는 풀리지 않음
  • 미업데이트 기준 일수는 관리자가 1~365일 사이에서 정합니다(17.6). 기준이 14일이면 13일째까지는 정상이고, 14일째부터 경고가 붙습니다.
  • 두 경고가 함께 붙으면 배지가 두 개(기한초과, 미업데이트 순) 붙고, 목록 행 배경은 기한초과의 빨강으로 칠해집니다(미업데이트만이면 노랑). 기한초과인 Deal은 목록의 Due 칸도 빨간 굵은 글씨로 강조됩니다. 색만으로 구분하지 않도록 항상 글자 배지가 함께 보입니다.
  • 경고가 보이는 곳: Deals 목록(Deal 이름 옆 배지·행 색·Due 강조), Deal 상세 탭의 Deal 정보 'Next Action' 행 옆, Actions 탭 표에서 지금 기준이 되는 Action(Next Action이 있는 가장 최근 Action)의 Due Date 옆(기한초과 배지만, 이전 Action의 지난 Due Date에는 붙지 않음)입니다. Deals 목록 위에는 두 배지의 뜻을 알려 주는 범례("기한초과 – Next Action의 Due Date가 지났습니다", "미업데이트 – N일 이상 미업데이트")가 있습니다.
  • Deals 목록의 기한초과·미업데이트 체크박스로 경고가 붙은 Deal만 골라 볼 수 있습니다. 배지와 같은 규칙이라 체크박스로 고른 Deal에는 해당 배지가 붙어 있습니다(12.1).
  • Status 체류 일수: 지금 Status에 들어온 날부터 며칠째인지 보여 줍니다(들어온 날은 0일). Status가 실제로 바뀔 때만 다시 0부터 셉니다. 다른 항목을 고쳐도 초기화되지 않습니다. 체류 일수는 Deal 상세 탭 Deal 정보의 Status 옆에 "N일째"(들어온 날은 "0일째")로 보이며, 마우스를 올리면 지금 Status로 바뀐 시각이 보입니다.
  • 모든 날짜 계산은 서버 시간대의 달력 날짜를 기준으로 서버가 합니다. 화면은 서버가 준 값을 그대로 보여 줍니다.

10. 고객·파트너 연락처

연락처는 Deal과 따로 저장되는 공용 데이터입니다. 같은 고객 담당자를 여러 Deal에서 함께 씁니다.

10.1 입력 규칙

  • 회사명(200자)과 담당자명(100자)은 필수이고, 공백을 넣을 수 없습니다. 예를 들어 "네오인 주식회사"가 아니라 "네오인"처럼 씁니다.
  • 직급, 이메일, 전화는 선택입니다.
  • 연락처의 종류(고객/파트너)는 만든 뒤에 바뀌지 않습니다.

10.2 같은 사람 판정

Deal 폼에서 연락처를 새로 입력하면, 시스템은 같은 종류·같은 회사·같은 담당자명의 기존 연락처가 있는지 먼저 찾습니다.

  1. 입력에 이메일이 있으면, 같은 이메일(대소문자 무시)을 가진 기존 연락처를 같은 사람으로 봅니다.
  2. 그런 연락처가 없으면, 이메일이 비어 있는 기존 연락처를 같은 사람으로 봅니다. 입력한 이메일이 그 연락처에 채워집니다.
  3. 입력에 이메일이 없으면, 회사·이름이 같은 기존 연락처를 같은 사람으로 봅니다.

같은 사람으로 판정되면 새로 만들지 않고 기존 연락처를 씁니다. 회사명·담당자명은 기존 표기를 유지합니다. 입력이 비어 있는 직급·이메일·전화는 기존 값을 지우지 않고, 입력한 값만 덮어씁니다.

10.3 정보 변경과 삭제

  • Deal 상세에서 연락처 정보를 고치면 연락처 자체가 바뀝니다. 그 연락처를 쓰는 모든 Deal의 History에 변경이 기록됩니다.
  • 파트너를 바꾸거나 해제해도 이전 연결은 지워지지 않고 해제 시각과 함께 보존됩니다.
  • 관리자는 Admin → contacts 관리 화면에서 연락처를 검색·등록·수정·삭제합니다. 어떤 Deal이든 고객이나 파트너(과거 연결 포함)로 쓰고 있는 연락처는 삭제할 수 없습니다.

11. 첨부 파일

  • Deal마다 파일을 올릴 수 있습니다. 첨부 파일은 Deal 상세 화면의 Deal 상세 탭(기본 탭)에 있습니다. 파일 하나는 최대 100MB이고, 설명은 100자까지 쓸 수 있습니다.
  • 실행·설치 파일은 올릴 수 없습니다: exe msi bat cmd sh ps1 jar com scr dmg pkg deb rpm vbs vbe wsf wsh hta cpl msp mst apk appimage run. setup.exe.처럼 끝에 점이나 공백을 붙여도 막힙니다.
  • 경로 문자(/, \), 제어 문자, 보이지 않는 서식 문자가 들어간 이름은 거절됩니다. 이름이 바뀌어 보이게 하는 위장을 막기 위해서입니다.
  • 같은 Deal에 같은 이름의 파일이 이미 있으면 교체할지 건너뛸지 묻습니다. 교체는 업로드한 본인, 퇴사한 영업이 올린 파일이면 다른 영업, 그리고 admin이 할 수 있습니다.
  • 파일은 서버의 저장 위치(관리자가 지정한 디렉터리) 아래 Deal code별 폴더에 보관됩니다. 저장 위치가 설정되지 않았거나 쓸 수 없으면 업로드가 거절됩니다.
  • 업로드·교체·삭제는 History에 남습니다. 내려받기는 로그인한 모든 사용자가 할 수 있습니다.

12.2 조건 유지

  • 검색 조건(기한초과·미업데이트 체크 포함), 정렬, 페이지는 화면 주소(URL)에 들어갑니다. 주소를 복사해 동료에게 보내면 같은 결과가 보입니다. 조건을 바꾸면 첫 페이지로 돌아갑니다.
  • 최종 업데이트 기간은 고른 순간의 날짜로 주소에 저장됩니다. 그래서 “최근 2주”로 만든 주소를 다음 날 열면 같은 날짜 범위가 보이고, 선택 상자는 “직접 지정”으로 표시됩니다.
  • 상세 화면에 갔다가 Deals 메뉴로 돌아와도 마지막 조건과 정렬이 복원됩니다. 이 기억은 사용자별로, 브라우저 탭 세션 동안만 유지됩니다.
  • "초기화"는 검색 조건과 정렬을 모두 기본값(연도 올해, 나머지 '전체', 최종 업데이트 ▼)으로 되돌립니다. 기억한 조건이 없을 때 메뉴로 들어와도 같은 기본값입니다. 초기화 직후 브라우저 뒤로 가기를 누르면 직전 조건으로 돌아갑니다.
  • 남아 있던 마지막 조건을 직접 지우면(예: 키워드만 있던 상태에서 키워드를 지움) 올해가 다시 붙지 않고 연도가 '전체'가 됩니다. 올해로 되돌리려면 "초기화"를 누르세요.
  • Dashboard에서 숫자를 눌러 목록으로 오면 그 조건이 새 기억이 됩니다. 이전에 기억한 조건·정렬·페이지는 남지 않습니다(14.4).

13. Forecast

Forecast 메뉴는 담당자별로 Forecast(수주 가능성)마다 Deal이 몇 건, 얼마인지 모아 보여 줍니다. Forecast Review 미팅에서 담당자별 합계를 보고, 담당자를 골라 그 담당자의 Deal을 같은 화면에서 확인하는 용도입니다. 모든 역할이 볼 수 있고, 이 화면에서 바꿀 수 있는 값은 없습니다.

13.1 무엇을 세나

  • 기준 날짜는 Expected Close(매출일)입니다. Won이면 실제 매출일입니다. 고른 연도·분기·월에 Expected Close가 들어가는 Deal만 셉니다.
  • Deal 목록과 항상 일치합니다. 같은 조건으로 Deals 목록을 조회하면 건수와 금액이 같습니다(Lost 제외).
  • 열은 Commit · Most Likely · Best · Pipeline, 그 합계인 Total(Open), 그리고 Won(별도)입니다. Lost는 세지 않습니다. 각 칸은 "건수 · 금액(단위:천원)"입니다.
  • 맨 아래 합계 행은 담당자 행을 더한 값입니다. Open도 Won도 없는 담당자는 표에 나오지 않습니다. 퇴사한 담당자의 Deal도 그대로 셉니다.
  • 위쪽 카드는 고른 기간의 Open 합계와 Won 합계입니다.

13.4 월말 스냅숏

  • 매월 1일 00:05(서버 시간)에 서버가 자동으로 지난달 말 기준 Forecast 값을 저장합니다. 사람이 입력하는 값은 없습니다.

  • 저장에 실패한 달은 관리자가 서버에서 다시 실행합니다. 다시 계산할 수 있는 달은 지난달과 이번 달뿐이며, 다시 실행하면 그 달 값이 새로 바뀝니다.

14.1 탭과 조건

  • 탭은 Status(처음 열면 이 탭)와 Forecast 두 개이며 화면 맨 위(제목 바로 아래)에 있습니다. 조건 입력란은 각 탭 안의 맨 위에 있습니다. 조건은 탭마다 따로입니다(2026-10-28): Status 탭에서 바꾼 연도·Quarter·담당자·Vendor는 Forecast 탭에 영향을 주지 않고, 탭을 바꾸면 그 탭에서 마지막으로 고른 조건이 그대로 보입니다. 한 번 본 조건의 결과는 탭을 오가도 바로 보입니다.
  • 조건은 연도(기본 올해, 항상 선택), Quarter(연도 바로 오른쪽의 Q1~Q4 버튼, 두 탭 모두), 담당자(퇴사자 포함), Vendor입니다. Quarter 버튼은 여러 개를 함께 누를 수 있고 고른 분기만 조회합니다. 아무것도 누르지 않은 것과 넷 다 누른 것은 같은 '전체'입니다(넷 다 누르면 버튼은 눌린 채 보입니다). Quarter·담당자·Vendor는 처음에 아무것도 고르지 않은 '전체'입니다. 연도에는 '전체'가 없습니다. 연도 선택지는 Deal의 Expected Close 중 가장 이른 연도부터 내년까지입니다(올해·내년은 Deal이 없어도 항상 보임, 주소에 범위 밖 연도가 들어 있으면 그 연도도 더해 보임).
  • 예전 주소(탭 구분 없는 year·owner·vendor는 두 탭 모두에, quarter는 Status 탭에만)로 들어와도 같은 조건으로 열립니다. 예전 Selected Quarter 주소 값(sq)은 무시합니다.
  • 기간은 Expected Close 기준입니다(Won이면 실제 매출일). Expected Close는 Deal 등록 때 필수라 모든 Deal이 어느 한 연도에 속합니다.
  • 탭과 두 탭의 조건은 모두 화면 주소(URL)에 들어가므로 새로고침하거나 주소를 공유해도 같은 화면이 보입니다. Dashboard 조건은 따로 기억하지 않아 메뉴로 다시 들어오면 기본값(올해·전체)입니다.
  • 금액은 다른 화면처럼 천원 단위입니다. 조건 아래 안내 줄("기간은 Expected Close 기준이며 금액 단위는 천원입니다. 기준일 YYYY-MM-DD")에 기준일(서버 날짜)이 표시됩니다. 조건에 맞는 Deal이 없으면 "조건에 맞는 Deal이 없습니다."가 보입니다.

  • 이번 달·이번 분기 Expected Close: 오늘(서버 날짜)이 속한 달·분기에 Expected Close가 있는 Open Deal(Won·Lost 제외) 수입니다.

14.4 숫자를 누르면 Deals 목록으로

막대(또는 막대 조각), 타일, 전체 Status Pipeline 표의 Status 이름·합계, Quarter Closing Forecast 표의 숫자 칸을 누르면 그 숫자를 만든 조건이 검색 조건으로 자동 등록된 채 Deals 목록으로 이동합니다. 목록의 "총 N건"과 금액 합은 누른 숫자와 같습니다. 팝업은 열리지 않습니다. Status 표의 건수·금액 칸과 분기 표의 분기 이름(Q1~Q4)은 누를 수 없습니다. Lost 제외·Open 합계 같은 숫자는 목록의 Forecast 조건에 해당 Forecast들을 모두 골라 넘깁니다(관리자가 추가한 Open 코드도 포함). 넘길 Forecast가 하나도 없으면 그 숫자는 누를 수 없습니다.

15. Reports

Reports 메뉴에서는 필요한 표를 직접 설계해 조회하고, 결과가 마음에 들면 이름을 붙여 저장합니다. Deal과 Deal Actions 두 데이터에서 컬럼을 골라 섞을 수 있고, 같은 값끼리 묶어 합계·건수를 내고, 결과로 차트를 만듭니다. 모든 역할이 쓸 수 있습니다(15.10). 이 화면은 조회만 하며 Deal 값을 바꾸지 않습니다.

  • 저장하는 것은 결과 데이터가 아니라 설계(컬럼·조건·정렬·행 수·차트 설정)입니다. 저장한 리포트는 열 때마다 최신 데이터로 다시 조회합니다.
  • SQL을 직접 쓰거나 고칠 수는 없습니다. 화면에서 고르면 서버가 SQL을 만들고, 만든 SQL은 읽기 전용으로만 보여 줍니다(15.7).
  • 데이터 범위는 Deals 목록과 같습니다. 모든 역할이 모든 Deal을 대상으로 조회합니다.
  • 금액은 다른 화면처럼 기본 천원 단위로 보이고, 날짜·시각과 "올해" 같은 기간은 서버 시간대 기준입니다.

  • 앞 N자만 보기(2026-10-28): 모든 컬럼에 켤 수 있는 표시 옵션입니다. 켜면 N 칸(기본 20, 1~200)이 열리고, 포맷을 적용한 글자 중 앞 N자만 보이며 넘치면 "…"가 붙습니다. 결과 표의 칸과 차트의 범주 축·범례에만 적용되고, 합계 행·차트 툴팁·데이터 레이블은 전체 값을 보입니다. 잘린 칸에 마우스를 올리면 전체 값이 보입니다. 그룹핑과 정렬·조건은 전체 값 기준이라 앞 글자가 같은 서로 다른 값이 같은 글자로 여러 줄 보일 수 있습니다. 예전에 텍스트 "앞 N자" 포맷으로 저장한 리포트는 열 때 이 옵션(같은 N)으로 바뀌어 보입니다.
  • 컬럼 설정의 그룹핑을 켜면 그 컬럼 값이 같은 행끼리 하나로 묶입니다. 여러 컬럼을 켜면 그 조합으로 묶습니다(예: Vendor × 분기).
  • 그룹핑한 컬럼이 하나라도 있으면 나머지 컬럼은 모두 집계가 됩니다.
    • 숫자 컬럼: 합계 · 평균 · 최소 · 최대 중 하나. 기본은 합계이고 Status 체류 일수만 평균입니다.
    • 숫자가 아닌 컬럼: 건수 · 고유 건수 중 하나만 고를 수 있습니다. 고르지 않고 조회하면 "그룹핑할 때 이 컬럼은 집계(건수 또는 고유 건수)를 골라야 합니다. 그룹핑하거나 빼세요"가 나옵니다.
    • Action 건수는 집계가 건수로 정해져 있습니다.
  • 그룹핑이 없으면 집계 없이 행 값이 그대로 나옵니다. 이때 집계 칸은 "(그룹핑이 있을 때)"로 잠겨 있습니다.
  • 구성비(%)는 그룹핑한 결과의 합계·건수 컬럼에서만 계산됩니다. 각 그룹 값이 전체 합계에서 차지하는 비율입니다.

15.5 조건

조건 한 줄은 필드 · 연산자 · 값입니다. 필드 목록의 "+조건"이나 조건 칸의 "+ 조건 추가"로 넣고, 줄마다 삭제할 수 있습니다. 조건은 최대 20개이며, 조건이 없으면 모든 Deal이 대상입니다(Action 단위 리포트는 모든 Action).

형식연산자값
텍스트포함 · 같음 · 시작 · 비어 있음 · 비어 있지 않음글자(200자 이내)
코드·사용자다음 중 하나 · 다음이 아님 · 비어 있음목록에서 여러 개 선택(최대 100개)
숫자= · ≠ · > · ≥ · < · ≤ · 범위정수. 금액은 천원 단위로 입력합니다(입력란 옆 "(천원)").
날짜·시각범위 · 이전 · 이후 · 상대 기간날짜, 또는 기간 선택
  • 조건 결합: 조건 칸 위의 선택 하나로 정합니다. "모든 조건을 만족(AND)" 또는 "하나라도 만족(OR)"입니다. 한 리포트 안에서 AND와 OR를 섞거나 괄호로 묶을 수는 없습니다.
  • 상대 기간: 올해 · 이번 분기 · 이번 달 · 최근 N일(N은 1~3650) · 오늘 이전. 조회할 때마다 서버 날짜로 다시 계산합니다. 그래서 "올해"로 저장한 리포트는 내년에 열면 내년 데이터를 봅니다. 고정된 날짜가 필요하면 "범위"를 쓰세요.
  • 범위는 시작·끝을 모두 넣고 양끝을 포함합니다. 시작이 끝보다 크면 "시작이 끝보다 클 수 없습니다"가 나옵니다.

15.6 데이터 범위 표시와 Deal당 한 번 합계

디자이너 맨 위의 데이터 범위 표시는 결과 표의 한 행이 무엇인지 늘 알려 줍니다. 컬럼·조건을 바꿀 때마다 바로 바뀝니다.

Deal Actions 필드를 쓴 곳표시결과의 한 행
쓰지 않음"행 단위: Deal 1건"Deal 1건
컬럼에 있음(Action 건수 포함)"행 단위: Action 1건 · Deal과 Join(Action이 없는 Deal은 빠짐)"Action 1건. Deal 정보는 그 Deal의 Action마다 반복되고, Action이 하나도 없는 Deal은 결과에 없습니다.
조건에만 있음"행 단위: Deal 1건 · 조건에 맞는 Action이 있는 Deal만"Deal 1건. 조건에 맞는 Action이 하나라도 있는 Deal만 남고 행은 늘지 않습니다.
  • Action 조건이 여러 개일 때, AND면 "(같은 Action 하나가 모든 Action 조건을 만족)", OR면 "(Action 조건 중 하나를 만족하는 Action이 있는 Deal)"이 덧붙습니다. AND는 한 Action이 모든 Action 조건을 함께 만족해야 한다는 뜻입니다.
  • 예: "이번 달 미팅을 한 Deal의 금액 합계"는 Action 유형과 수행일시를 조건에만 넣으면 Deal 단위로 정확히 나옵니다.

Deal 금액 합계·평균과 Deal 필드 건수는 Deal마다 한 번만 셉니다. 행이 Action 단위여도 Deal 숫자(금액·Users·Status 체류 일수)의 합계·평균과, Deal 필드(예: Deal code)의 건수·고유 건수는 그 Deal을 한 번만 셉니다.

예: 금액 1억 원(100,000천원)인 Deal에 Action이 3건 있으면, 담당자로 그룹핑한 결과에서 금액 합계는 1억(3억이 아님), Deal code 건수는 1, Action 건수는 3입니다. 최소·최대는 원래 중복의 영향을 받지 않습니다.

이 규칙이 적용되면 데이터 범위 표시에 "Deal 숫자(금액 등)는 Deal마다 한 번만 더합니다"가 함께 보입니다.

그룹핑하지 않은 Action 단위 결과는 행 값 그대로이므로, 같은 Deal의 금액이 Action 행마다 반복해 보입니다. 이 반복 값을 직접 더하지 말고 그룹핑과 합계를 쓰세요.

15.7 조회와 결과

  • 정렬: 컬럼 하나를 고르고(기본 "(정렬 없음)") 오름차순·내림차순을 정합니다. 최대 행: 100 · 1,000(기본) · 10,000 중에서 고릅니다.
  • "조회"를 누르면 결과가 아래에 나옵니다(컬럼이 하나도 없으면 누를 수 없음, 조회 중에는 "조회 중…"). 결과 위에 "총 N행 · 조회 0.21초"가 보입니다. 그룹핑한 리포트에서 N은 그룹 수입니다. 최대 행보다 많으면 "총 N행 중 M행 표시(최대 행 수 제한)"로 보입니다.
  • 결과 표는 100행씩 페이지로 나뉩니다. 숫자는 오른쪽 정렬이고, 비어 있는 값은 "—"로 보입니다. 요일 포맷은 "2026-10-27 (화)"처럼 날짜 뒤에 요일이 붙습니다.
  • 조회한 뒤 설계를 바꾸면 "설계가 바뀌었습니다. '조회'를 눌러 다시 조회하세요"가 보입니다. 결과 표는 다시 조회할 때까지 이전 결과입니다.
  • 합계 행: 그룹핑하고 집계 컬럼이 있으면 "합계 행" 체크박스가 생깁니다. 켜면 표 맨 아래에 첫 그룹 열이 "합계"인 행이 붙습니다. 합계 행은 화면에 보이는 행을 더한 값이 아니라, 조건에 맞는 전체 데이터를 그룹 없이 한 번 더 집계한 값입니다. 그래서 최대 행 제한으로 잘린 그룹도 포함하고, 평균·고유 건수도 전체 기준으로 맞게 나옵니다.
  • Deal당 한 번 규칙이 적용된 결과에서는 한 Deal이 여러 그룹에 나오면 그룹마다 한 번씩 더하므로, 합계 행 아래에 "한 Deal이 여러 그룹에 나오면 그룹마다 한 번씩 더하므로 그룹 값의 합이 합계 행보다 클 수 있습니다"가 보입니다.
  • 오류 표시: 설계에 맞지 않는 곳이 있으면 결과 자리에 "고칠 곳 N개"와 위치(예: "컬럼 2(금액(원))", "조건 1(Status)")가 나오고, 해당 칩·조건 칸에도 표시됩니다.
  • 시간 제한: 조회는 서버에서 10초 안에 끝나야 합니다. 넘으면 "조회가 10초 안에 끝나지 않았습니다. 조건을 좁히거나 컬럼을 줄이세요"가 나옵니다. 그룹핑한 리포트는 합계 행까지 두 번 계산하므로 기다리는 시간이 최대 20초쯤 될 수 있습니다.
  • 생성 SQL 보기(읽기 전용): 결과 아래를 펼치면 서버가 만든 SQL을 볼 수 있습니다. 조회 전에는 "조회하면 서버가 만든 SQL이 여기에 보입니다"가 보입니다. 이 SQL은 확인용이라 고칠 수 없고, SQL을 직접 쓰는 입력란도 없습니다. 리포트를 저장할 때 함께 저장되지만, 실행은 항상 저장된 설계로 SQL을 새로 만들어 합니다.

15.8 저장·열기·편집

저장 버튼은 조회가 성공했고 그 뒤로 설계를 바꾸지 않았을 때만 켜집니다. 꺼져 있을 때 마우스를 올리면 "먼저 조회하세요" 또는 "바뀐 설계를 다시 조회한 뒤 저장하세요"가 보입니다. 누르면 리포트 저장 대화상자가 열립니다.

항목규칙
이름필수, 앞뒤 공백 제거 후 100자 이내. 모든 리포트 사이에서 하나뿐이어야 하며 대소문자만 달라도 같은 이름으로 봅니다. 다른 사람의 비공개 리포트도 포함하므로, 목록에 없는 이름도 "같은 이름의 리포트가 이미 있습니다."로 거절될 수 있습니다.
설명선택, 1,000자 이내. 목록에 보이고 검색에 쓰입니다.
공개 범위"모든 사용자에게 보임" 또는 "나만 보기". 나만 보기는 만든 사람과 admin만 볼 수 있습니다. 바꿀 수 있는 사람은 만든 사람과 admin뿐이고, 다른 사람에게는 "공개 범위는 만든 사람 또는 admin만 바꿀 수 있습니다"와 함께 잠겨 보입니다.

대화상자에는 "저장 내용: 컬럼·조건·정렬·행 수·차트 설정과 생성 SQL. 결과 데이터는 저장하지 않고 열 때마다 다시 조회합니다."가 안내됩니다.

동작어디서결과
저장(새 리포트)새 리포트 화면의 "저장"새 리포트가 만들어지고, 화면이 그 리포트의 편집 화면으로 바뀝니다.
저장(덮어쓰기)편집 화면의 "저장"같은 리포트를 지금 설계로 바꿉니다. 화면은 그대로 편집 화면입니다.
다른 이름으로 저장편집 화면지금 설계를 새 이름의 새 리포트로 저장하고 그 편집 화면으로 갑니다. 원래 리포트는 그대로입니다. 만든 사람은 내가 됩니다.
복제목록의 ⋯ 메뉴, 보기 화면저장된 설계와 차트를 그대로 복사한 새 리포트를 만듭니다. 이름은 "원래 이름 복사본"으로 채워지고 공개 범위는 "모든 사용자에게 보임"으로 시작합니다(둘 다 바꿀 수 있음). 만든 사람은 내가 됩니다. 원본의 차트 설정을 읽을 수 없으면 차트 없이 복제됩니다.
되돌리기 / 초기화편집 화면 "되돌리기", 새 리포트 화면 "초기화"확인 뒤 편집 화면은 저장된 설계로 되돌리고("저장된 설계로 되돌릴까요?"), 새 리포트 화면은 컬럼과 조건을 모두 지웁니다("설계를 모두 지울까요?").
삭제목록의 ⋯ 메뉴, 보기 화면확인 뒤 지웁니다. 되돌릴 수 없습니다. 만든 사람과 admin만 할 수 있습니다.
  • 보기 화면(/reports/{id}): 열 때마다 저장된 설계로 다시 조회합니다. 제목 아래에 만든 사람·최종 수정 시각이 보이고, 버튼은 "다시 조회", "편집", "복제", "삭제"(권한에 따라)입니다. 차트가 저장된 리포트는 차트 탭으로 열립니다.
  • 저장 안 됨: 저장된 설계와 지금 설계가 다르면 제목 옆에 "● 저장 안 됨"이 붙습니다. 차트 설정을 바꿔도 붙습니다.
  • 떠날 때 확인: 저장하지 않은 변경이 있을 때 앱 안의 링크(상단 메뉴 등)를 누르면 "저장하지 않은 변경이 있습니다" 창이 "저장하지 않은 변경이 사라집니다. 이 화면을 떠날까요?"와 함께 열립니다. "떠나기"를 누르면 이동하고 "머물기"를 누르면 남습니다. 새로고침이나 탭 닫기는 브라우저가 직접 확인 창을 띄웁니다. 브라우저의 뒤로 가기와 로그아웃은 묻지 않고 바로 이동하니 주의하세요.
  • 동시에 편집할 때: 내가 편집 화면을 연 뒤 다른 사람이 같은 리포트를 먼저 저장했다면, 내 덮어쓰기는 "다른 사용자가 먼저 이 리포트를 저장했습니다. 다시 불러온 뒤 수정하거나 다른 이름으로 저장하세요."와 함께 거절되고 아무것도 바뀌지 않습니다. 내 설계를 지키려면 "다른 이름으로 저장"을 쓰고, 상대의 변경을 보려면 리포트를 다시 여세요.
  • 리포트를 찾을 수 없거나 볼 권한이 없으면 "리포트를 찾을 수 없습니다. 삭제되었거나 볼 권한이 없습니다."가 보입니다. 다른 사람의 비공개 리포트 주소를 열어도 같은 안내입니다.
  • 리포트를 만들거나 수정한 사용자는 나중에 사용자 관리에서 삭제해도 퇴사 처리되며, 리포트에는 "이름(퇴사)"로 남습니다(17.7).

15.9 차트

결과 카드의 "차트" 탭에서 결과 표를 엑셀처럼 차트로 그립니다. 차트는 그룹핑한 결과로만 만들 수 있습니다. 그룹핑이 없으면 "그룹핑한 결과로 차트를 만들 수 있습니다", 그룹핑 컬럼이 3개 이상이면 "차트는 그룹핑 컬럼이 1~2개일 때 만들 수 있습니다"가 보이고 "차트 만들기"를 누를 수 없습니다. "차트 만들기"를 누르면 그룹핑 컬럼과 집계 컬럼으로 기본 차트가 채워지고, 오른쪽 설정 패널에서 고칩니다. "차트 삭제"로 지울 수 있습니다.

  • 행/열 전환: 가로축 항목과 색으로 나뉘는 항목(계열 또는 값)을 맞바꿉니다. 막대·누적·꺾은선·영역에서만 씁니다.
  • 설정: 차트 제목, 범례(위 · 오른쪽 · 아래 · 숨김), 데이터 레이블(막대·점 위에 값 표시, 결과 표와 같은 포맷), 가로축 제목·세로축 제목, 세로축 최소·최대(비우면 자동, 최대는 최소보다 커야 함), 보조 축(콤보만). 가로 막대는 축이 돌아가므로 "세로축 제목(범주)", "가로축 제목(값)", "가로축 최소·최대"로 보입니다. 그 종류에서 쓸 수 없는 설정은 잠기고 마우스를 올리면 이유가 보입니다.
  • 범주 값이 비어 있으면 "(없음)"으로 보입니다. 최대 행 제한으로 잘린 결과는 "최대 행 수 제한으로 표시된 행만 차트에 그렸습니다"와 함께 받은 행만 그립니다. 범주가 너무 많으면 "범주가 너무 많아 차트를 그리지 않습니다(최대 1,000개). 조건을 좁히세요"가 보입니다.
  • 설정을 바꾸면 미리보기가 바로 바뀝니다. 설정이 덜 됐으면 "설정을 완성하면 차트가 그려집니다", 컬럼을 새로 넣어 아직 조회하지 않았으면 "조회하면 차트에 반영됩니다"가 보입니다. 차트가 쓰던 컬럼을 빼거나 그룹핑을 끄면 그 선택은 자동으로 풀립니다.
  • 차트는 리포트와 함께 저장되고(차트 없이 저장해도 됨), 목록의 "차트" 열에 종류가 보입니다. 보기 화면의 차트는 읽기 전용이며 저장된 차트가 없으면 "이 리포트에는 저장된 차트가 없습니다. 편집 화면에서 만들 수 있습니다."가 보입니다.
  • 저장된 차트 설정을 읽을 수 없으면 리포트는 차트 없이 열리고 "저장된 차트 설정을 읽을 수 없어 차트 없이 열었습니다. 차트를 다시 만들어 저장하세요."가 보입니다. 저장된 차트가 지금 결과와 맞지 않으면 "차트 설정이 지금 결과와 맞지 않습니다. 편집에서 고치세요"가 보입니다.
  • 차트나 결과 표를 눌러 Deals 목록으로 이동하는 기능(Drill-down)은 없습니다.

16. Deal 삭제

  • Owner 본인(영업)이나 admin만 삭제할 수 있습니다. 다른 사람 Deal을 연 영업 사용자에게는 '삭제' 버튼이 회색(누를 수 없음)으로 보이고, 마우스를 올리면 "본인 Deal 또는 admin만 삭제할 수 있습니다."가 나옵니다. 조회자(user)에게는 버튼이 보이지 않습니다.
  • 삭제는 되돌릴 수 없는 물리 삭제입니다. History, Action, 파트너 연결, BANT 선택, 첨부 파일(디스크의 파일 포함)이 함께 지워집니다.
  • 삭제 전에 함께 지워질 History·Action·첨부 건수를 보여 주고, 실수를 막기 위해 Deal code를 정확히 입력해야 삭제됩니다.
  • 연락처, 사용자, 코드, BANT Label, Vendor 같은 공용 데이터는 Deal을 삭제해도 남습니다.

종결된 Deal은 삭제하지 말고 Won 또는 Lost로 남겨 두세요. 삭제는 잘못 만든 Deal을 정리할 때만 씁니다.

17. 관리자 설정

관리자 설정은 상단 Admin 메뉴(admin에게만 보임)에서 엽니다. 화면 제목은 Admin > Settings이고, 왼쪽 하위 메뉴는 사용자 관리 / Deal 관리 / contacts 관리 / 외부연동입니다. Deal 관리에는 Status 코드, Forecast 코드, BANT Label, Action 유형, Vendor, 경고 기준 탭이 있습니다.

17.1 최초 설정(설치 직후 한 번)

admin 사용자가 아직 없으면 접속하자마자 설정 화면(/setup)이 열립니다. 세 단계를 순서대로 진행합니다.

  1. AD 서버 등록: 로그인에 쓸 사내 AD(LDAP) 서버 주소와 계정 조회 방식을 입력합니다. 별도 시험 버튼은 없고, "AD 서버 등록"을 누르면 서버가 연결을 시험해 실패하면 저장하지 않습니다.
  2. 파일 저장 위치: 첨부 파일을 둘 서버의 절대 경로를 입력합니다. "쓰기 테스트"로 미리 확인할 수 있고, 등록할 때도 시스템이 실제로 써 보고 확인합니다.
  3. 관리자 등록: AD 아이디와 비밀번호를 입력합니다. 처음 등록하는 AD 계정이 첫 관리자(admin)가 됩니다.

설정이 끝난 뒤에는 Admin → 외부연동 화면에서 AD 설정과 저장 위치를 바꿀 수 있습니다. 이 화면에서는 두 설정 모두 저장하기 전에 "연결 테스트"·"쓰기 테스트"로 시험할 수 있습니다.

17.2 코드 관리(Status·Forecast)

  • 코드를 추가하고, 이름을 바꾸고, 순서를 바꾸고, 삭제할 수 있습니다. 이름은 같은 종류 안에서 대소문자 무시로 중복될 수 없고 50자 이내입니다.
  • Forecast 코드 표의 확률 참고 열에 기본 코드의 확률 구간(예: 51–75)이 보입니다. 화면에서는 확률 참고를 입력하거나 고칠 수 없고, 새로 추가한 코드는 '-'로 보입니다.
  • 새로 추가한 Forecast 코드는 항상 진행 중(Open) 구분이 되어 표의 '구분' 열에 Open으로 보이고, Open 합계에 들어갑니다(14.4).
  • 시스템 규칙에 연결된 코드는 잠금 상태입니다. Status의 기회발굴·계약완료, Forecast의 Pipeline·Won·Lost가 여기에 해당합니다. 이 코드는 이름과 순서만 바꿀 수 있고 삭제할 수 없습니다.
  • Deal이나 Action 스냅숏에서 쓰고 있는 코드는 삭제할 수 없습니다. 화면에 사용 건수가 표시됩니다.
  • Status·Forecast 순서는 목록에서 Status·Forecast 헤더로 정렬할 때의 순서가 됩니다.

17.3 BANT Label 관리

  • 기본 Label이 미리 들어 있습니다. 예: Budget에는 "단독 예산 확보", "예산 작업중", "미확인" 등이 있습니다.
  • 영업 담당자는 Deal 등록·수정·상세 화면의 BANT 입력란에 목록에 없는 이름을 입력해 저장하면 새 Label을 만들 수 있습니다(별도 추가 버튼은 없습니다). 이름 변경과 삭제는 admin만 할 수 있습니다.
  • Label 이름은 같은 구분 안에서 대소문자 무시로 중복될 수 없고 50자 이내입니다. Deal이 쓰고 있는 Label은 삭제할 수 없습니다.

17.4 Action 유형 관리

  • Admin → Deal 관리의 Action 유형 탭에서 admin이 유형을 추가하고, 이름을 바꾸거나 삭제합니다. 영업 담당자는 이 탭에 들어갈 수 없지만, Action 입력란에 목록에 없는 이름을 입력해 저장하면 새 유형을 만들 수 있습니다.
  • 기본 유형 8개(통화, 미팅, 이메일, 데모, 제안, 협상, 계약, 기타)가 미리 들어 있고, 잠겨 있지 않아 이름을 바꾸거나 지울 수 있습니다.
  • 이름은 앞뒤 공백을 제거하고 50자 이내이며, 대소문자 무시로 중복될 수 없습니다.
  • 이름을 바꾸면 그 유형을 쓰는 모든 Action에 새 이름이 보입니다. Action이 쓰고 있는 유형은 삭제할 수 없고, 화면에 사용 건수("Action N건")가 보입니다.

17.5 Vendor 관리

  • Admin → Deal 관리의 Vendor 탭에서 Vendor를 추가·이름 변경·삭제합니다. admin만 할 수 있고, 다른 역할은 목록을 보고 Deal에서 고르기만 합니다.
  • 이름은 앞뒤 공백을 제거하고 100자 이내이며, 대소문자 무시로 중복될 수 없습니다. 목록은 이름순입니다.
  • 이름을 바꾸면 그 Vendor를 쓰는 모든 Deal에 새 이름이 보입니다.
  • Deal이 쓰고 있는 Vendor는 삭제할 수 없고, 화면에 사용 건수("Deal N건")가 보입니다. 삭제 전에 확인을 받습니다.
  • Solution은 이 탭에서 관리하지 않고 Deal마다 직접 입력합니다(5장 입력 항목). Vendor마다 소속 Solution을 추가·이름 변경·삭제했습니다(2026-10-22 변경). 예전에 Deal이 쓰던 Solution 이름은 그 Deal의 Solution 텍스트로 옮겨졌습니다.

Vendor를 하나도 등록하지 않으면 Deal에서 고를 Vendor가 없습니다. 운영을 시작하기 전에 관리자가 Vendor를 먼저 등록하세요.

17.6 경고 기준

미업데이트 기준 일수(1~365일, 기본 14일)를 정합니다. 바꾸면 모든 Deal의 경고가 즉시 새 기준으로 계산됩니다.

17.7 사용자 관리

  • Admin → 사용자 관리에서 AD 아이디, 이름, 역할(admin/sales/user)로 사용자를 등록합니다(AD 아이디나 이름을 비우면 "AD 아이디와 이름을 입력하세요."). 등록된 사용자만 로그인할 수 있습니다. 비밀번호는 시스템에 저장되지 않고, 로그인할 때마다 AD로 확인합니다.
  • 이름과 이메일은 로그인할 때 AD 정보로 갱신됩니다.
  • 역할 변경(2026-10-26 추가): 재직 중인 다른 사용자 행의 "역할 변경"을 누르면 역할을 고르는 확인 창이 열립니다. 바뀐 역할은 그 사용자의 다음 요청부터 적용되며 다시 로그인할 필요는 없습니다. sales를 다른 역할로 바꿔도 이미 Owner인 Deal은 그대로 남지만, 새 Deal의 Owner로는 지정할 수 없습니다. 다음 경우는 바꿀 수 없습니다: 자기 자신("자기 자신의 역할은 바꿀 수 없습니다."), 재직 admin이 한 명뿐일 때 그 사람을 다른 역할로("마지막 관리자의 역할은 바꿀 수 없습니다."), 퇴사자, 개발용 로그인 사용자. 역할 변경 이력은 따로 남지 않습니다.
  • 사용자를 삭제하면 다음과 같이 처리됩니다.
    • Deal·Action·History·리포트(만들거나 수정한 리포트) 등에 기록이 남아 있으면 퇴사 처리합니다. 목록에서는 빠지지만 기록에는 "이름(퇴사)"로 남습니다.
    • 기록이 하나도 없으면 완전히 지웁니다.
  • 삭제하면 그 사용자의 로그인 세션은 모두 끝납니다. 결과는 "… 사용자가 삭제되었습니다." 또는 "… 사용자가 퇴사 처리되었습니다."로 알려 줍니다.
  • 사용자 목록은 위의 상태로 재직 / 퇴사 / 전체를 골라 봅니다(기본 재직).
  • 자기 자신과 마지막 남은 admin은 삭제할 수 없습니다.
  • 퇴사자가 재입사하면 같은 아이디로 다시 등록합니다. 이때 새 사용자로 만들어지며, 예전 기록은 퇴사한 계정에 남습니다.

18. 로그인과 계정

  • 사내 AD 아이디와 비밀번호로 로그인합니다.
  • 로그인 상태는 기본 8시간 유지됩니다.
  • 비밀번호를 연속으로 틀리면 잠깁니다.
    • 한 아이디로 15분 안에 5번 틀리면, 그 아이디는 15분 동안 로그인할 수 없습니다.
    • 같은 PC(IP)에서 15분 안에 30번 틀리면, 그 IP도 15분 동안 막힙니다.
    • 이 값들은 운영 설정으로 바꿀 수 있습니다.
  • 개발 환경(local·dev)에서만 로그인 화면에 빠른 로그인(관리자/영업/조회자) 버튼이 보입니다. 운영 서버에는 이 기능이 없습니다.

20. 자주 묻는 질문

"Status와 Forecast의 동기화가 맞지 않습니다."가 나와요.

수정 폼에서 계약완료와 Won 중 하나만 골랐을 때 나옵니다. 둘을 함께 맞추거나, 목록·상세 화면에서 하나만 바꾸세요. 하나만 바꾸면 시스템이 나머지를 맞춰 줍니다.

"Won·계약완료로 바꾸려면 매출금액과 매출일이 필요합니다."가 나와요.

Deal을 Won으로 닫을 때는 확정된 매출금액과 매출일을 함께 입력해야 합니다.

금액이 원보다 1000배 작게 보여요.

금액은 모든 화면에서 천원 단위로 보입니다(항목 이름의 (단위:천원)). 예를 들어 100,000은 1억 원입니다. 입력할 때도 천원 단위로 입력하세요. 예전 History 행에는 원 단위 문구("…원")가 남아 있을 수 있습니다. 금액 입력란은 숫자와 콤마만 받으므로 소수점 같은 다른 문자는 사라집니다. 예를 들어 1,500.50을 붙여넣으면 150,050이 되니 붙여넣은 뒤 값을 확인하세요.

Deal을 고쳤는데 미업데이트 경고가 그대로예요.

미업데이트는 Action 기준입니다. Deal 자체를 고치는 것(목록·상세에서 바로 고치기 포함)은 마지막 업데이트를 바꾸지 않으므로 경고가 풀리지 않습니다. 진행 상황을 Action으로 남기면(진행사항만 적어도 됨) 경고가 풀립니다.

Next Action을 종료했는데 기한초과가 그대로예요.

기한초과는 Next Action 상태와 상관없이 Due Date만 봅니다. 종료한 Next Action도 Due Date가 지났으면 기한초과로 보이며, 상태 라벨(종료(수행)·종료(미수행))로 구분합니다. 다음 계획을 담은 새 Action을 남기면 그 Action이 기준이 됩니다.

Deals 목록에서 BANT Label로 검색할 수 없어요.

목록의 BANT Label 검색 조건은 2026-10-22에, 목록의 BANT 열은 2026-10-23에 없어졌습니다. BANT는 행을 펼친 빠른 보기나 상세 화면에서 확인하세요. 예전에 북마크한 주소에 BANT 조건이 남아 있어도 그 조건만 무시되고 목록은 정상으로 보입니다. 챙겨야 할 Deal을 찾을 때는 '기한초과'·'미업데이트' 체크박스를 쓰세요(12.1).

다른 사람의 Deal을 고칠 수 있나요?

영업 역할이면 수정은 가능하며 History에 고친 사람이 남습니다. 삭제는 Owner 본인과 admin만 할 수 있습니다.

Deal 등록 화면에 Vendor 목록이 비어 있어요.

Vendor는 관리자가 등록한 목록에서만 고릅니다. Admin → Deal 관리 → Vendor 탭에서 먼저 등록해야 합니다(17.5).

예전 Deal을 수정하는데 "Solution을 입력하세요."가 나와요.

Solution은 2026-10-22부터 직접 입력하는 필수 항목입니다. 그전에 Solution이 비어 있던 Deal은 “—”로 보이며, 폼으로 저장하려면 Solution을 입력해야 합니다. "Solution을 선택하려면 Vendor를 먼저 선택하세요."·"선택한 Solution은 이 Vendor에 속하지 않습니다."는 Solution을 목록에서 고르던 때의 문구로 더 나오지 않습니다(2026-10-22 변경). "선택한 Vendor가 없습니다."는 그사이 관리자가 Vendor를 지운 경우이니 목록에서 다시 고르면 됩니다.

Action 유형이나 BANT에 "목록에 없는 ○○입니다. 저장하면 새 ○○로 추가됩니다."가 보여요.

입력한 이름과 같은 항목이 없다는 뜻입니다. 오타라면 후보에서 고르고, 정말 새 항목이면 그대로 저장하세요. 대소문자만 다른 이름은 기존 항목으로 저장되므로 이 안내가 보이지 않습니다.

"이미 있는 유형 이름입니다."·"사용 중인 유형은 삭제할 수 없습니다. (Action N건)"이 나와요.

유형 이름은 대소문자 무시로 중복될 수 없습니다. 같은 이름을 다른 사람이 막 만들었다면 다시 저장하면 그 유형으로 저장됩니다. Action이 쓰고 있는 유형은 지울 수 없으니 이름을 바꾸거나 그대로 두세요.

Owner를 관리자로 지정할 수 없어요.

Owner는 재직 중인 영업 역할 사용자만 될 수 있습니다. 관리자에게 Deal을 맡기려면 그 사람을 영업 역할로 등록해야 합니다.

연락처 회사명에 띄어쓰기를 넣을 수 없어요.

같은 회사가 "네오인 주식회사"와 "네오인"처럼 다르게 쌓이는 것을 막으려고 공백을 금지합니다. 회사를 구분하는 핵심 이름만 붙여서 입력하세요.

Forecast 합계가 Deals 목록에서 센 것과 달라요.

Forecast는 Lost를 세지 않고, 기간을 Expected Close로 거릅니다. Deals 목록에서 같은 연도·Quarter(또는 월)·담당자·Vendor를 고르고 Forecast를 Lost가 아닌 값으로 보면 같은 숫자가 나옵니다. “기준 시점”이 월말 스냅숏이면 그달 말의 값이라 지금 목록과 다를 수 있습니다(13장).

Deals 목록에 다른 연도 Deal이 안 보여요.

조건 없이 Deals 목록에 들어오거나 초기화하면 연도가 올해로 정해집니다(2026-10-26부터). 다른 연도나 모든 연도의 Deal을 보려면 검색 조건의 연도를 그 연도나 '전체'로 고르세요(12.1).

Dashboard 숫자와 Deals 목록 건수가 달라요.

Dashboard에서 숫자를 눌러 들어온 목록은 같은 조건이라 건수·금액이 같습니다. 직접 조건을 고른 목록과 비교한다면 다음을 확인하세요. Status 막대·합계는 Lost를 빼므로 Forecast를 Lost가 아닌 것 모두("Lost 제외")로, Open 합계는 Won·Lost가 아닌 것 모두("Open 전체")로 골라야 합니다. 기간은 Expected Close 기준입니다. 주의 필요 Deal·Closing Attention 타일은 연도·Quarter를 따르지 않습니다(14장).

“기준 시점”에 지난달이 없어요.

월말 스냅숏은 매월 1일 00:05에 저장됩니다. 서버가 꺼져 있었으면 켜진 뒤 실행되고, 실패했으면 관리자가 서버에서 다시 실행해야 합니다. 다시 실행할 수 있는 달은 지난달과 이번 달뿐입니다.

리포트에 Action 필드를 넣었더니 행이 늘어났어요.

Deal Actions 필드를 컬럼에 넣으면 결과의 한 행이 Action 1건이 됩니다. Deal 단위로 보려면 Action 필드를 조건에만 넣으세요. 그러면 조건에 맞는 Action이 있는 Deal만 남고 행은 Deal 1건입니다. 화면 맨 위의 데이터 범위 표시에서 지금 행 단위를 확인할 수 있습니다(15.6).

Action 단위 리포트에서 금액 합계가 Action 수만큼 부풀지 않나요?

부풀지 않습니다. 그룹핑한 결과에서 Deal 금액·Users·Status 체류 일수의 합계·평균과 Deal 필드 건수는 Deal마다 한 번만 셉니다. 1억 원 Deal에 Action이 3건이면 금액 합계는 1억입니다. 다만 한 Deal이 여러 그룹(예: Action 유형별)에 나오면 그룹마다 한 번씩 들어가므로, 그룹 값을 모두 더하면 합계 행보다 클 수 있습니다(15.7).

리포트 "저장" 버튼이 눌리지 않아요.

먼저 "조회"를 눌러 결과를 확인해야 저장할 수 있습니다. 조회한 뒤 컬럼·조건을 바꿨다면 다시 조회하세요. 결과가 지금 설계와 같아야 저장됩니다.

"같은 이름의 리포트가 이미 있습니다."가 나오는데 목록에는 그 이름이 없어요.

리포트 이름은 다른 사람의 비공개 리포트까지 포함해 전체에서 하나뿐이어야 하고, 대소문자만 다른 이름도 같은 이름으로 봅니다. 다른 이름을 쓰세요.

"다른 사용자가 먼저 이 리포트를 저장했습니다. 다시 불러온 뒤 수정하거나 다른 이름으로 저장하세요."가 나와요.

편집 화면을 연 뒤 다른 사람이 같은 리포트를 먼저 저장했습니다. 내 변경은 저장되지 않았습니다. 내 설계를 남기려면 "다른 이름으로 저장"을 쓰고, 상대의 변경을 반영하려면 리포트를 다시 열어 고치세요.

"조회가 10초 안에 끝나지 않았습니다. 조건을 좁히거나 컬럼을 줄이세요"가 나와요.

조회할 데이터가 너무 많습니다. 기간 조건(예: Expected Close 올해)을 더하거나, 필요 없는 컬럼·그룹을 빼거나, 최대 행을 줄여 보세요.

작년에 저장한 리포트를 열었더니 결과가 달라졌어요.

리포트는 결과가 아니라 설계를 저장하므로 열 때마다 최신 데이터로 다시 조회합니다. "올해"·"이번 분기"·"최근 N일" 같은 상대 기간은 여는 날의 서버 날짜로 다시 계산됩니다. 특정 기간을 고정하려면 조건을 "범위"로 바꾸세요.

차트 탭에 "그룹핑한 결과로 차트를 만들 수 있습니다"가 보여요.

차트는 그룹핑한 결과로만 만듭니다. 범주로 쓸 컬럼(예: Vendor)의 컬럼 설정에서 그룹핑을 켜고, 금액 같은 숫자 컬럼은 합계로 두고 다시 조회한 뒤 차트를 만드세요(15.9).

리포트를 열면 "저장된 설계가 지금 규칙과 맞지 않습니다. 편집에서 고치세요"가 나와요.

저장한 뒤 서버 규칙이나 목록 값이 바뀌어 그 설계로는 조회할 수 없다는 뜻입니다. 아래에 보이는 항목을 편집 화면에서 고쳐 다시 저장하세요. 편집 화면도 열리지 않으면 리포트를 삭제하고 새로 만드세요.

업로드가 "사용할 수 없는 파일 이름입니다."로 거절돼요.

파일 이름에 경로 문자나 보이지 않는 특수 문자가 들어 있을 수 있습니다. 이름을 새로 입력해 저장한 뒤 다시 올려 보세요.
